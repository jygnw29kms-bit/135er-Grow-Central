01 / VISION

Aus einem Fan-Controller wird eine sichere Automationsplattform.

Das Projekt entstand aus der DF100M-Integration. Die neue v0.6-Architektur trennt Geräteprotokolle, Steuerlogik, Smart-Home-Brücken und Cloud sauber voneinander. Der Raspberry Pi bleibt die Instanz, die lokal entscheidet.

LOCAL-FIRST

Funktioniert ohne Cloud

Gerätesteuerung und Sicherheitslogik bleiben lokal. Internetdienste sind Erweiterungen, keine Voraussetzung.

MODULAR

Adapter statt Spezialfälle

Shelly, Home Assistant und spätere Geräte sprechen über eine normalisierte interne Geräteschicht.

SAFE BY DEFAULT

Steuern erst nach Freigabe

Entdeckung bedeutet niemals Schreibrecht. Geräte werden einzeln registriert, freigegeben und autorisiert.

02 / ARCHITEKTUR

Der Pi bleibt der Master.

Smart-Home-Systeme und Cloud sind angeschlossene Dienste – nicht die Kontrollebene.

▲ inbound internet blocked by default◆ local adapters are allowlisted● commands are audited

04 / SECURITY

Vier Hürden vor jedem Schaltbefehl.

Smart Plugs schalten reale elektrische Verbraucher. Deshalb wird ein Gerät nicht allein durch Discovery steuerbar.

  1. 01
    Inventory

    Gerät muss serverseitig bekannt sein.

  2. 02
    Approval

    Gerät muss explizit freigegeben sein.

  3. 03
    Write permission

    Schreibrecht wird separat gesetzt.

  4. 04
    Authenticated command

    Geschützte Writes benötigen lokalen API-Token und Audit.
